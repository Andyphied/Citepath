# ING-006 Implementation Note

## Summary

Added `GET /workspaces/{workspace_id}/ingestion-jobs/{job_id}` so workspace members with `VIEW_DOCUMENTS` can read ingestion job status (`pending`, `processing`, `completed`, `failed`) with sanitized error messages. Document detail (`DOC-004`) continues to expose `latest_job` for the same fields.

## Files Changed

| File | Purpose |
|------|---------|
| `app/modules/ingestion/exceptions.py` | `IngestionJobNotFoundError` |
| `app/modules/ingestion/service.py` | `get_job()` with error sanitization |
| `app/api/routes/ingestion.py` | Workspace-scoped job status route |
| `app/api/ingestion_errors.py` | 404 handler |
| `app/api/deps.py` | `IngestionServiceDep` |
| `app/main.py` | Register ingestion router and exception handler |
| `tests/unit/test_ingestion_service.py` | `get_job` unit tests |
| `tests/api/test_ingestion_jobs.py` | API integration tests |

## Behavior Added

- `GET /workspaces/{workspace_id}/ingestion-jobs/{job_id}` with `VIEW_DOCUMENTS` RBAC
- Returns `IngestionJobResponse`: `id`, `workspace_id`, `document_id`, `status`, `attempt_count`, `error_message`, `started_at`, `completed_at`, `created_at`
- `error_message` sanitized via `sanitize_ingestion_error_message()` (same as document detail)
- 404 when job is missing or belongs to another workspace
- Worker already sets `processing` → `completed`/`failed` and document `indexed`/`failed` on terminal states

## Tests Added

**Unit:**

- `test_get_job_returns_sanitized_response`
- `test_get_job_raises_when_missing`

**API (Docker):**

- Processing job returns `status=processing`
- Completed job returns `status=completed`; linked document is `indexed`
- Failed job returns sanitized `error_message`
- Cross-workspace job access returns 404

## Decisions Made

- Dedicated job endpoint reuses `IngestionJobResponse` and document-detail sanitization rather than duplicating logic
- `VIEW_DOCUMENTS` permission used (Admin/Member/Owner/Viewer with read access) — aligns with document detail visibility; ADMIN-002 can aggregate these endpoints later
- `attempt_count` exposed as API field (story's `retry_count` maps to model column)

## Known Limitations

- No job list/history endpoint (single job by ID only)
- No admin-wide cross-workspace job listing (deferred to ADMIN-002)
