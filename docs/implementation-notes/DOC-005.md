# DOC-005 Implementation Note

## Summary

Implemented `DELETE /workspaces/{workspace_id}/documents/{document_id}` with `DOCUMENT_MUTATE` permission enforcement. Deletion removes document chunks, ingestion jobs, the document row, the stored file, and emits a minimal `document.deleted` audit event. The endpoint returns `204 No Content`.

## Behavior Added

- `DELETE /workspaces/{workspace_id}/documents/{document_id}` requires Owner, Admin, or Member (`DOCUMENT_MUTATE`); Viewer receives `403 forbidden`.
- Workspace-scoped lookup: cross-workspace document id returns `404 document_not_found`.
- Deletes all `document_chunks` for the document (embeddings included).
- Deletes all `ingestion_jobs` referencing the document (no DB CASCADE on FK).
- Deletes the `documents` row after audit flush.
- Removes the stored file when `storage_key` is present; missing file is a no-op.
- Emits audit event `document.deleted` with `document_id` and `title` metadata (minimal; full AUDIT-002 deferred).

## Decisions Made

- Explicitly delete `ingestion_jobs` before removing the document because the initial migration FK has no `ON DELETE CASCADE`.
- Storage file deleted after DB commit so a storage failure does not leave a searchable document without a row.
- Audit event uses `document.deleted` with `document_id` and `title` only; actor and IP are persisted on the audit row per repository defaults (full AUDIT-002 enrichment deferred).
- `LocalStorageBackend.delete` is idempotent for missing files to tolerate partial prior cleanup.

## Known Limitations

- Deletion is not a single DB transaction across chunk, job, audit, and document steps; partial failure could require manual cleanup.
- No soft-delete path (optional P2 per story notes).
- S3 storage `delete` not implemented (local backend only).
- Full audit metadata snapshot and query UI deferred to AUDIT-002 / AUDIT-007.
