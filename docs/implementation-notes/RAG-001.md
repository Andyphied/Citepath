# RAG-001 Implementation Note

## Summary

Exposed `POST /workspaces/{workspace_id}/query` for synchronous RAG Q&A with JWT auth, workspace membership, `QUERY_RAG` permission (Viewer allowed), conversation create/continue, and full retrieve → answer pipeline.

## Files Changed

- `app/api/routes/queries.py`
- `app/api/rag_errors.py`
- `app/api/deps.py`
- `app/main.py`
- `app/modules/rag/query_service.py`
- `app/modules/rag/repository.py`
- `app/modules/rag/schemas.py`

## Behavior Added

- Accepts `question` and optional `conversation_id`.
- Creates RAG conversation when `conversation_id` is omitted; validates ownership when provided.
- Appends user and assistant messages per turn.
- Returns `conversation_id`, `message_id`, `answer`, `confidence`, `citations`, `suggested_followups`, `insufficient_context`.
- Sanitizes embedding/completion provider failures to generic 502/503 responses.

## Tests Added

- `tests/api/test_rag_query.py`
- `tests/security/test_rag_workspace_isolation.py`
- `tests/integration/test_rag_query_service.py`

## Decisions Made

- Sync response for MVP (no Celery/async job).
- Conversation list/detail APIs remain out of scope (RAG-006/007).

## Known Limitations

- No request `filters` parameter yet (RET-004 dependency).

## Follow-up Items

- RAG-006/007 conversation APIs and multi-turn list/detail UX.

- **USAGE-001:** each successful answer logs embedding + chat completion usage events.
