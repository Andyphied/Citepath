## Behavior Added

- `/login` and `/register` centered product-branded forms
- Valid login/register stores JWT cookie, seeds session user, redirects through `sanitizeNextPath(next)` (default `/`)
- Invalid credentials stay on `/login` with inline API error
- App shell header shows authenticated email; Log out calls `POST /auth/logout`, clears cookie, navigates to `/login`
- Middleware continues to redirect unauthenticated protected routes to `/login?next=…`
- Home shows empty-workspace prompt when memberships list is empty

## Decisions Made

- **JS-readable `atlasops_token` cookie retained (not HttpOnly).** The API client injects `Authorization: Bearer` from JS, and Next middleware gates on cookie presence. Moving to HttpOnly would require FastAPI cookie auth (or a BFF) and `credentials: "include"` CORS changes — out of scope for UI-002. Hardened with `SameSite=Lax` and `Secure` when the page is HTTPS.
- AUTH-003 folded in: logout acknowledgment only; client discard is authoritative.
- Post-login “first workspace” is the existing workspace switcher selection on `/`; no per-workspace UI routes yet. Empty memberships show an on-page prompt (create-workspace UI is a later story).

## Known Limitations

- Token readable by XSS (same as UI-001 MVP stance)
- No OAuth / password reset
- Workspace creation still API-only
- Logout does not revoke JWT server-side until a future blocklist
