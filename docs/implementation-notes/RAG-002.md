# RAG-002 Implementation Note

## Summary

Implemented retrieval orchestration in `RagQueryService` calling `RetrievalService.search()` with workspace and user context, then compressing initial `k=8` results to at most five chunks with full content loaded for downstream prompting.

## Files Changed

- `app/modules/rag/query_service.py`
- `app/modules/rag/schemas.py`
- `app/modules/rag/repository.py`

## Behavior Added

- Retrieval runs only after `PermissionService.require(QUERY_RAG)` succeeds.
- Qualifying chunks are trimmed to top 4–5 (max 5) by score for LLM context.
- Full chunk text is loaded from `IngestionRepository` while previews remain for citations.

## Tests Added

- `tests/integration/test_rag_query_service.py`
- `tests/api/test_rag_query.py`
- `tests/security/test_rag_workspace_isolation.py`

## Decisions Made

- Reused existing `RetrievalService.search()` instead of duplicating embed/search logic.
- Compression is score-only (no reranker) per MVP scope.

## Known Limitations

- Metadata filters (RET-004) are not exposed on the query API in this batch.

## Follow-up Items

- RET-004 metadata filters on `POST /query` when implemented.

- **USAGE-001:** embedding usage logged via existing retrieval path.
