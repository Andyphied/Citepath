# RET-003 Implementation Note

## Summary

Extended the retrieval pipeline to return up to 8 scored chunks with `chunk_id`, `content_preview`, `citation_id` (chunk UUID), document metadata, and an `insufficient_context` flag when no chunks meet `RETRIEVAL_MIN_SCORE` (default 0.72).

## Files Changed

| File | Change |
|------|--------|
| `app/modules/ingestion/repository.py` | `SimilarChunkResult` + `search_similar_with_scores()` |
| `app/modules/retrieval/schemas.py` | `RetrievedChunk`, `RetrievalSearchResult`, preview length constant |
| `app/modules/retrieval/service.py` | Score filtering, ordering, document metadata enrichment |
| `tests/unit/test_retrieval_service.py` | Score ordering, threshold flagging, preview truncation |

## Behavior Added

- Returns up to `top_k` (default 8) chunks ordered by descending cosine similarity score.
- `citation_id` equals `chunk_id` (stable chunk UUID for UI linking).
- `content_preview` truncated to 200 characters.
- `document_metadata` includes document title, source/file type, and chunk JSON metadata.
- `insufficient_context=True` when zero chunks qualify or all scores are below threshold.

## Tests Added

- `tests/unit/test_retrieval_service.py` — descending score order, below-threshold flag, empty results, preview truncation
- `tests/integration/test_retrieval_service.py` — scored results with document metadata from DB

## Decisions Made

- Score computed in SQL as `1 - cosine_distance` per RAG architecture doc.
- Chunks below threshold are excluded from `chunks` list (not returned with flag only); RAG receives empty list + `insufficient_context=True`.
- Document metadata loaded per unique `document_id` with in-request cache to avoid N+1 queries.

## Known Limitations

- No metadata filtering (RET-004).
- No separate `confidence` enum; RAG layer derives high/medium/low from scores.
- Preview length fixed at 200 chars (RET-005 may refine).
