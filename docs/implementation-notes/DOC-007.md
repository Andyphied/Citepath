# DOC-007 Implementation Note

## Summary

Closed the document status API contract by documenting the worker-driven state machine on `DocumentStatus`, adding human-readable `status_label` to all document API responses, and adding acceptance-level tests for upload→processing→indexed and failure→failed transitions.

## Files Changed

| File | Purpose |
|------|---------|
| `app/infrastructure/db/enums.py` | Document status state machine docs and `label` property |
| `app/modules/documents/schemas.py` | `status_label` field and `DocumentResponse.from_document()` |
| `app/modules/documents/service.py` | Use `from_document()` for upload, list, detail, reindex |
| `docs/06-api-design.md` | Document `status_label` on upload/list/detail responses |
| `tests/unit/test_document_status.py` | Enum labels and response mapping tests |
| `tests/unit/test_document_service.py` | Upload response includes `status_label` |
| `tests/api/test_document_status.py` | API transition and label exposure tests |

## Behavior Added

- Document responses include both `status` (machine value) and `status_label` (human-readable)
- Labels: `uploaded` → "Uploaded", `processing` → "Processing", `indexed` → "Indexed", `failed` → "Failed"
- State machine documented on `DocumentStatus` enum (worker-driven transitions; re-index paths included)
- Applies to upload (`202`), list, detail, and reindex responses

## Tests Added

**Unit:**

- `test_document_status_label` — all four enum labels
- `test_document_response_from_document_maps_status_and_label` — response mapping per status
- `test_document_status_worker_transition_order` — lifecycle order contract
- `test_upload_persists_document_and_creates_ingestion_job` — asserts `status_label`

**API (Docker):**

- `test_upload_ingestion_success_exposes_indexed_status_labels` — upload→indexed on upload/list/detail
- `test_upload_ingestion_failure_exposes_failed_status_labels` — failure→failed with labels
- `test_upload_transitions_through_processing_before_terminal_state` — worker sets `processing` on start

## Decisions Made

- Kept existing worker transition logic unchanged (ING-001/005/006); DOC-007 is the document-facing contract only
- Added `status_label` alongside `status` rather than replacing machine values (UI can bind badges to either)
- Centralized label mapping on `DocumentStatus.label` with `DocumentResponse.from_document()` factory

## Known Limitations

- Ingestion job responses still expose machine `status` only (ING-006 scope)
- Upload response may already show terminal status when Celery runs eagerly in tests/production
