# ING-001 Implementation Note

## Summary

On document upload, the API now creates a workspace-scoped `ingestion_jobs` row with status `pending`, enqueues the Celery task `process_ingestion_job`, and returns `202 Accepted` with `{ document, ingestion_job }`. The worker validates `workspace_id`/`document_id`, transitions the job and document to `processing`, and leaves a stub pipeline body for ING-002+.

## Behavior Added

- `IngestionJobRepository.create` persists a job with status `pending` scoped to `workspace_id`.
- `IngestionService.create_job_for_document` commits the job row then calls `process_ingestion_job.delay(job_id, workspace_id, document_id)`.
- `DocumentService.upload` creates the document, then delegates to `IngestionService`.
- `POST /workspaces/{workspace_id}/documents` returns `202` with `{ "document": {...}, "ingestion_job": { "id", "status": "pending", ... } }`.
- Celery task validates job/document workspace alignment, skips terminal jobs, sets job → `processing` and document → `processing`, then stops (pipeline stub).

## Decisions Made

- Enqueue occurs after the job repository commits, per ADR-004, avoiding races on missing job rows.
- Task payload includes `workspace_id` and `document_id` for worker-side isolation checks without trusting job row alone.
- Pipeline body is intentionally a no-op after status transitions; ING-002+ will add extract/chunk/embed steps.
- Celery tasks register via explicit import after broker bootstrap to avoid placeholder-app registration issues.
- API tests reload the Celery module after env setup so tasks bind to the configured app with eager execution.

## Known Limitations

- Worker stub leaves documents/jobs in `processing` until ING-002 completes the pipeline.
- No `document_upload` audit event (AUDIT-001 deferred).
- No Celery autoretry wiring yet (ING-007 / OBS-005 deferred).
- Re-index flow not integrated (DOC-006 deferred).
