# RET-002 Implementation Note

## Summary

Implemented workspace-scoped vector search through `RetrievalRepository`, which delegates to `IngestionRepository.search_similar_with_scores()` from ING-005. SQL always includes `workspace_id` via `_scoped_filter`; results are never post-filtered in application memory.

## Files Changed

| File | Change |
|------|--------|
| `app/modules/ingestion/repository.py` | Added `search_similar_with_scores()`; `search_similar()` delegates to it |
| `app/modules/retrieval/repository.py` | Thin wrapper over ingestion search |
| `app/modules/retrieval/service.py` | Calls repository after embedding |
| `tests/security/test_retrieval_workspace_isolation.py` | Identical-content A/B isolation via `RetrievalService` |
| `tests/integration/test_retrieval_service.py` | End-to-end search against pgvector |

## Behavior Added

- Default `top_k=8` on `RetrievalService.search()`.
- Cosine similarity ordering via pgvector `cosine_distance`.
- Workspace A searches return only Workspace A chunks even when identical content exists in Workspace B.

## Tests Added

- `tests/security/test_retrieval_workspace_isolation.py` — identical content across two workspaces
- `tests/integration/test_retrieval_service.py` — pgvector retrieval pipeline
- Existing `tests/security/test_workspace_isolation.py::test_search_similar_excludes_other_workspace_chunks` still covers repository-level isolation

## Decisions Made

- Extended `IngestionRepository` with `search_similar_with_scores()` instead of duplicating SQL in retrieval; `search_similar()` now delegates to preserve ING-005 behavior.
- `RetrievalRepository` wraps ingestion search to keep retrieval module boundary clean without bypassing workspace filter.

## Known Limitations

- No metadata filters yet (RET-004).
- No HTTP route; service-only for RAG/agent consumers.
