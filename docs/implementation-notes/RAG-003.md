# RAG-003 Implementation Note

## Summary

Added grounded answer generation via `ChatCompletionProvider` (OpenAI implementation), prompt builder with version `rag-grounded-v1`, structured JSON output (facts, recommendations, follow-ups), and chat completion usage logging.

## Files Changed

- `app/infrastructure/llm/completion.py`
- `app/infrastructure/llm/openai_completion.py`
- `app/infrastructure/llm/types.py`
- `app/infrastructure/llm/factory.py`
- `app/modules/rag/prompt_builder.py`
- `app/modules/rag/completion.py`
- `app/modules/rag/query_service.py`

## Behavior Added

- System prompt forbids inventing procedures not present in CHUNK blocks.
- LLM returns JSON with answer, facts, recommendations, cited chunk IDs, and follow-ups.
- `prompt_version` stored on assistant message metadata and logged in usage metadata.
- Provider failures mapped to generic HTTP 503 via `ChatCompletionError`.

## Tests Added

- `tests/unit/test_rag_prompt_builder.py`
- `tests/integration/test_rag_query_service.py`
- `tests/api/test_rag_query.py`

## Decisions Made

- OpenAI JSON response format for predictable parsing in MVP.
- Confidence derived from retrieval scores (`high` / `medium` / `low`).

## Known Limitations

- Anthropic chat provider deferred; factory currently wires OpenAI only.
- No streaming.

## Follow-up Items

- Anthropic completion provider when `LLM_PROVIDER=anthropic` is required for chat.

## Co-shipped Coverage

- **RAG-005:** LLM skipped when `insufficient_context=True`; template refusal response returned instead.
- **USAGE-001:** `UsageOperation.CHAT_COMPLETION` events logged with tokens, latency, model, and `purpose=rag_answer`.

**Resolution:** Committed separately as `806a32a` (`docs(ret): mark RET-001–003 stories complete`).
