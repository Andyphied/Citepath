## Behavior Added

- `GET /metrics` returns Prometheus text exposition (`text/plain`) with registered counters.
- Each non-`/metrics` HTTP response increments `http_requests_total{method,path_template,status}`.
- Status codes ≥ 400 also increment `http_errors_total` with the same labels.
- Path labels use FastAPI route templates when available (e.g. `/workspaces/{workspace_id}/query`).
- Creating an ingestion job increments `ingestion_jobs_total{status="pending"}` in the API process; worker transitions increment `processing` / `completed` / `failed`.
- Every `UsageService.log_event` increments `llm_calls_total{operation,status}` (no workspace labels).

## Decisions Made

- **Library:** `prometheus_client` (story-preferred) over log-based fallback.
- **Auth:** Unauthenticated internal endpoint; document network-edge restriction. Matches story “auth optional” and common Prometheus scrape patterns.
- **Labels:** No `workspace_id` / `user_id` on metrics to avoid tenant-sensitive cardinality on a public scrape surface. Per-workspace usage stays in admin/usage APIs.
- **Histograms:** Deferred (story marks optional P2); latency still available via structured request logs (`duration_ms`).
- **Middleware order:** Metrics innermost so status codes reflect handler outcomes; request ID still outermost.
- **Worker metrics:** Counters in Celery workers are process-local; API `/metrics` reflects the API process. Job creation (API) and RAG LLM calls (API) are visible on the API scrape; terminal ingestion transitions and embedding calls in the worker are not unless worker metrics are scraped or multiprocess mode is added later.

## Known Limitations

- No HTTP / ingestion / LLM duration histograms yet.
- No shared registry across API + Celery workers.
- No auth or IP allowlist on `/metrics` (network policy assumed).
- `ingestion_failures_total` / richer OBS docs series deferred (OBS-005 / future).

## Gate 3 → Step 4 Fix Cycle (2026-07-24)

Gate 3 verdict: **REQUEST CHANGES**.

### Findings addressed

1. **Cardinality leak on unmatched routes:** `path_template_for_request` fell back to `request.url.path`, which would create unbounded Prometheus label values for 404/unmatched traffic. Now always returns the fixed label `unmatched` (`UNMATCHED_PATH_TEMPLATE`) when no route template is bound.
2. **Regression coverage:** Unit test asserts raw path is never used; API test hits a random non-route path and asserts `http_requests_total` / `http_errors_total` increment with `path_template="unmatched"` and that the raw path does not appear in scrape output.
3. **Optional (done):** HTTP methods normalized via allowlist (`GET`/`HEAD`/`POST`/`PUT`/`PATCH`/`DELETE`/`OPTIONS`) with `"OTHER"` for anything else, applied inside `observe_http_request`.
