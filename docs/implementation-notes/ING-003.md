# ING-003 Implementation Note

## Summary

Implemented token-based document chunking for extracted ingestion segments. The worker now splits `ExtractionResult` segments into overlapping `ContentChunk` outputs using `tiktoken` (`cl100k_base`), configurable chunk size and overlap via `Settings`, and logs `ingestion_chunking_completed`. Chunks are held in-memory; persistence is deferred to ING-005.

## Files Changed

| File | Purpose |
|------|---------|
| `pyproject.toml` | Added `tiktoken` dependency |
| `app/infrastructure/config.py` | `CHUNK_SIZE_TOKENS` and `CHUNK_OVERLAP_TOKENS` settings with validation |
| `app/modules/ingestion/chunker.py` | Paragraph-aware token chunker and `ContentChunk` output type |
| `app/modules/ingestion/tasks.py` | Wired chunking after extraction in `process_ingestion_job` |

| `tests/unit/test_ingestion_tasks.py` | Task wiring test for chunking call |
| `tests/unit/test_config.py` | Chunk settings defaults and validation |

## Behavior Added

- `chunk_extraction_result(...)` returns ordered `ContentChunk` list with `content`, `chunk_index`, and metadata.
- Tokenizer: `tiktoken` `cl100k_base` (embedding model approximation).
- Defaults: 1,000 target tokens, 150 overlap (overridable via env).
- Paragraph-aware splitting on blank lines before hard token cuts for oversized paragraphs.
- Markdown `#` headings detected as `section_heading`; prepended to chunk content when present.
- Chunk metadata includes `workspace_id`, `document_id`, `document_title`, `source_type`, `chunk_index`, optional `page_number` (from segment), optional `section_heading`.
- Worker logs `ingestion_chunking_completed` with `chunk_count`; job/document remain `processing`.

## Tests Added

**Unit:**

- `tests/unit/test_ingestion_chunker.py` — short doc single chunk, long doc multiple overlapping chunks, PDF `page_number` preservation, markdown heading detection

- `tests/unit/test_config.py` — chunk defaults and overlap validation

## Decisions Made

- Output type named `ContentChunk` to avoid collision with SQLAlchemy `DocumentChunk` model.
- `chunk_index` is 0-based and sequential, matching existing repository usage.
- Section headings from markdown update context for subsequent paragraphs within a segment stream.
- Overlap is applied as a decoded token suffix prepended to the next chunk body (after optional heading prefix).
- No DB writes in this story; `IngestionRepository.create_chunk` remains unused until ING-005.

## Known Limitations

- Hard token splits may break mid-word when a single paragraph exceeds `CHUNK_SIZE_TOKENS`.
- Section heading detection is markdown `#` prefix only; no PDF outline or font-based heading inference.
- Chunks spanning multiple PDF pages use the first page number found in contributing paragraphs.
- Chunk output is not persisted or passed beyond the worker task scope yet.
