# RET-001 Implementation Note

## Summary

Wired query embedding into `RetrievalService.search()` via the existing `embed_query_text()` helper from USAGE-002. Empty queries are rejected at the Pydantic validation layer before any provider call. Request-scoped embedding cache avoids duplicate provider calls within the same service instance.

## Files Changed

| File | Change |
|------|--------|
| `app/modules/retrieval/schemas.py` | `RetrievalSearchInput` with blank-query validator |
| `app/modules/retrieval/exceptions.py` | `EmptyQueryError`, `QueryEmbeddingError` |
| `app/modules/retrieval/service.py` | `_embed_query()` delegates to `embed_query_text()` |
| `tests/unit/test_retrieval_service.py` | Empty query, embedding failure, cache tests |

## Behavior Added

- Valid questions are embedded with the same provider/model path as ingestion chunks.
- `embedding_query` usage events are logged through `embed_query_text()`.
- Whitespace-only queries raise `EmptyQueryError`.
- Embedding provider failures raise `QueryEmbeddingError`.
- Repeated searches with the same query on one `RetrievalService` instance reuse the cached vector.

## Tests Added

- `tests/unit/test_retrieval_service.py` — empty query rejection, embedding failure, request-scoped cache

## Decisions Made

- Reused `embed_query_text()` from `app/modules/retrieval/embeddings.py` rather than duplicating usage logging.
- Validation lives in `RetrievalSearchInput` (Pydantic) per story requirement for validation-layer rejection.
- Request-scoped cache is an in-memory dict on `RetrievalService`; no cross-request cache.

## Known Limitations

- No HTTP route exposes retrieval yet (deferred to RAG stories).
- Cross-request embedding cache is out of scope (P2 per story).
