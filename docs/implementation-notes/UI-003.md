# UI-003 Implementation Note

## Summary

Replaced the `/documents` PageStub with a workspace-scoped documents page: multipart upload (role-gated), status-badge table, polling while ingestion is in flight, empty state, and inline success/error feedback. Hardened `apiFetch` so `FormData` uploads never force `Content-Type: application/json`.

## Behavior Added

- `/documents` lists workspace documents: title, file type, status badge (`status_label`), uploaded date, uploader
- Status badge colors: uploaded gray, processing yellow, indexed green, failed red
- Owner / admin / member see upload zone (drag-drop or picker) → `POST /workspaces/{id}/documents` multipart `file`
- Viewer sees read-only list (or empty) and a Viewer message — no upload control
- Polls every ~2.5s while any document is `uploaded` or `processing`
- Empty state: “Upload your first runbook”
- Inline feedback for upload progress / success / API errors
- `apiFetch` deletes any `Content-Type` header when `body` is `FormData` so the browser sets multipart boundary

## Decisions Made

- Poll on both `uploaded` and `processing` (not only `processing`) so the demo loop updates through the short uploaded→processing window
- Uploader column shows `"You"` when `uploaded_by` matches the session user; otherwise a truncated UUID (API has no uploader name)
- No toast library — lightweight `FeedbackBanner` matches existing shell styling
- Page size fixed at 50 for MVP (pagination UI out of scope)

## Known Limitations

- No delete / re-index UI (later stories)
- No infinite scroll / page controls for large corpora
- Uploader display is UUID-based, not email/name
- No browser E2E covering the full upload→indexed path in this story
