# WS-001 Implementation Note

## Summary

Implemented authenticated workspace creation via `POST /workspaces`. The endpoint accepts a workspace name and optional slug, auto-generates a URL-safe slug when omitted, assigns the creator as `owner` in `workspace_members`, and returns `id`, `name`, `slug`, and `created_at`. Duplicate explicit slugs return `409`; invalid slug format returns `422`.

## Behavior Added

- `POST /workspaces` requires a valid JWT (`CurrentUserDep`).
- Request body: `{ "name": "...", "slug": "..." }` where `slug` is optional.
- Slug auto-generated from name (lowercase, hyphens) when omitted; numeric suffix appended on collision.
- Explicit slug must match `^[a-z0-9]+(?:-[a-z0-9]+)*$`.
- Creator persisted as `workspace_members.role = owner` in the same transaction as workspace insert.
- Response `201`: `{ "id", "name", "slug", "created_at" }`.
- Errors: `401 unauthorized`, `409 duplicate_slug`, `422 invalid_slug`.

## Decisions Made

- Added slug via new Alembic revision (`002`) rather than editing `001`, preserving migration history for existing deployments.
- Auto-generated slug collisions append `-2`, `-3`, etc.; explicit duplicate slugs return `409` per acceptance criteria.
- Owner membership created atomically in repository (single commit) matching auth repository patterns.
- Invalid slug returns `422` (validation error) rather than `400`, consistent with structured API error format.
- Response omits `role` field; story specifies `id`, `name`, `slug`, `created_at` only (role available via membership queries / future list endpoint).

## Known Limitations

- No audit log event on workspace creation (deferred to audit stories).
- No `GET /workspaces` list endpoint (WS-002).
- API tests require Docker (testcontainers); skipped when Docker unavailable.
- Slug uniqueness race under concurrent identical explicit slugs relies on DB unique index + `IntegrityError` fallback in repository.
