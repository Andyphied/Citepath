# ING-005 Implementation Note

## Summary

Persisted embedded ingestion chunks to PostgreSQL/pgvector via bulk replace on `document_chunks`, completed the ingestion worker pipeline with job/document terminal status transitions, and verified workspace-scoped vector search.

## Files Changed

| File | Purpose |
|------|---------|
| `app/modules/ingestion/repository.py` | `replace_chunks_for_document()` — delete + bulk insert in one transaction |
| `app/modules/ingestion/chunk_storage.py` | `persist_embedded_chunks()` orchestration with `ChunkStorageError` |
| `app/modules/ingestion/tasks.py` | Wire storage after embedding; job → `completed`, document → `indexed` |
| `tests/unit/test_ingestion_repository.py` | Repository replace semantics |
| `tests/unit/test_ingestion_chunk_storage.py` | Persistence orchestration unit tests |
| `tests/unit/test_ingestion_tasks.py` | Full pipeline completion + storage failure wiring |
| `tests/integration/test_ingestion_chunk_storage.py` | pgvector insert + `search_similar` integration tests |

## Behavior Added

- After successful embedding, worker deletes existing chunks for the document and bulk-inserts `EmbeddedChunk` rows.
- On storage success: ingestion job → `completed` with `completed_at`; document → `indexed`.
- On storage failure: `_fail_ingestion` with truncated error message.
- Structured log: `ingestion_storage_completed` with `chunk_count`.
- Empty chunk list supported (delete-only replace for zero-chunk documents).

## Tests Added

**Unit:**

- `tests/unit/test_ingestion_repository.py` — delete + bulk insert, empty list
- `tests/unit/test_ingestion_chunk_storage.py` — success count, repository error mapping
- `tests/unit/test_ingestion_tasks.py` — pipeline completion, storage failure

**Integration:**

- `tests/integration/test_ingestion_chunk_storage.py` — persisted chunks queryable via `search_similar`; re-run replaces prior rows

## Decisions Made

- No new Alembic migration — existing `document_chunks` schema + HNSW index from INFRA-003 sufficient.
- `token_count` not stored as column (not in schema); metadata JSONB carries chunker fields.
- `replace_chunks_for_document` commits atomically (delete + insert) rather than reusing per-row `create_chunk()`.
- Re-index API (DOC-006) deferred; delete-before-insert supports future re-index semantics.

## Known Limitations

- Job/document status updates commit separately from chunk replace (multiple transactions on success path).
- No admin API yet to observe completed jobs (ING-006).
- Integration tests require Docker/testcontainers.
