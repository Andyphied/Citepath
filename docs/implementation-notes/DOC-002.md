# DOC-002 Implementation Note

## Summary

Extended document upload validation to reject empty files, unsupported extensions (including `.docx`), and PDF files that lack the `%PDF` magic-byte signature. Unsupported file type errors now include the allowed extension whitelist in response details. All validation runs before storage writes.

## Files Changed

| File | Purpose |
|------|---------|
| `app/modules/documents/exceptions.py` | Added `EmptyFileError`, `InvalidFileContentError` |
| `app/modules/documents/service.py` | Added `_validate_not_empty`, `_validate_content`; PDF magic-byte and UTF-8 text checks |
| `app/api/document_errors.py` | `allowed_types` in unsupported handler; new empty/invalid-content handlers |
| `app/main.py` | Registered new exception handlers |
| `stories/doc-002-file-type-validation.md` | Status set to `in_progress` |

## Behavior Added

- Rejects `len(file_content) == 0` with `422 empty_file` before storage.
- Rejects `.docx` and other non-whitelist extensions with `422 unsupported_file_type`.
- `unsupported_file_type` details include `allowed_types: ["json", "md", "pdf", "txt"]` and the rejected `extension`.
- PDF uploads must start with `%PDF`; otherwise `422 invalid_file_content` with `reason: invalid_pdf_signature`.
- `.md`, `.txt`, and `.json` uploads must be valid UTF-8 text; binary content returns `422 invalid_file_content` with `reason: invalid_text_encoding`.

- `.docx` extension rejection

- Fake `.pdf` upload → 422, no DB row, no storage file
- Extended `.exe` test to assert `allowed_types` in details

## Decisions Made

- Validation order: extension → size → empty → content, all before `storage.save`.
- PDF validation uses magic-byte prefix only (no full PDF structure parsing).
- Text validation is UTF-8 decodability for `md`, `txt`, and `json`; no JSON schema check.
- `allowed_types` is derived from `ALLOWED_EXTENSIONS` in the error handler to stay in sync.

## Known Limitations

- No MIME-type or filename/content-disposition cross-check beyond extension whitelist.
- JSON content is not validated as well-formed JSON.
- PDF validation does not verify a complete or parseable PDF document.
