# RAG-007 Implementation Note

## Summary

Verified and hardened multi-turn RAG follow-up behavior: subsequent queries with `conversation_id` reload prior messages into the prompt, re-run retrieval each turn, and log separate usage events per turn. Aligned prompt history window to 5 turns per RAG-006 engineering note.

## Files Changed

- `app/modules/rag/prompt_builder.py` (`MAX_HISTORY_TURNS = 5`)
- Existing `app/modules/rag/query_service.py` flow used without structural changes

## Behavior Added

- No new public endpoints; multi-turn continues via `POST /workspaces/{workspace_id}/query` with `conversation_id`.
- Turn 2+ includes prior user/assistant content under `CONVERSATION HISTORY` in the grounded prompt (last 5 turns).
- Each turn performs fresh vector retrieval and logs distinct `embedding_query` + `chat_completion` usage events when context is sufficient.

## Tests Added

- `tests/integration/test_rag_multi_turn.py`
  - API multi-turn flow with usage-event and prompt-history assertions
  - Service-level four-message persistence and dual retrieval/completion calls
  - History-window unit assertion in `tests/unit/test_rag_prompt_builder.py`

## Decisions Made

- Kept re-retrieval-on-every-turn behavior from RAG-001 rather than caching prior chunk sets.
- Used recording completion provider in integration tests to assert prior answer text appears in turn-2 prompt without brittle JSON parsing.

## Known Limitations

- History truncation drops turns older than 5 from the LLM prompt while full history remains in the database.
- Insufficient-context turns still append assistant refusal messages and do not log chat completion usage.

## Follow-up Items

## Platform follow-up

**Issue:** Migration `003_add_embedding_usage_operations` failed in testcontainers with `unsafe use of new value "embedding_document"` because PostgreSQL cannot use newly added enum values in the same transaction as `ALTER TYPE ADD VALUE`.

**Fix:** Wrap enum `ADD VALUE` statements in `op.get_context().autocommit_block()` before running the backfill `UPDATE` in `app/migrations/versions/003_add_embedding_usage_operations.py`.

**CI:** `.github/workflows/ci.yml` already runs `pytest tests/api tests/integration tests/security` with Docker on Ubuntu — no workflow change required once migration fix is merged.
