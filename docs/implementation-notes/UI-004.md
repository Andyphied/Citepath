## Behavior Added

- `/ask` posts to `POST /workspaces/{id}/query` with trimmed `question` and optional `conversation_id`
- Loading shows spinner + “Searching knowledge base…”; submit disabled until response completes
- Answers render a constrained markdown subset (paragraphs, headings, lists, bold/italic/code) after HTML escape
- Citations list document title, optional page/section metadata, expandable chunk preview + score
- Prior Q&A pairs stay in a session thread; follow-up chips re-submit using the same `conversation_id`
- `insufficient_context: true` uses amber “Insufficient context” styling (not the red error banner)
- Optional `?q=` prefill for repeatable demo screenshots; workspace change clears the thread

## Tests Added

- `web/src/lib/api/query.test.ts` — first-turn vs follow-up request bodies
- `web/src/lib/ask/ask.test.ts` — prefill, citation labels, XSS-safe markdown, thread append / followups, discard-when-workspace-changed mid-flight (`shouldApplyAskResponse`)

## Decisions Made

- Session thread is client-side for the demo loop; no conversation list/history API wiring in this story
- No new markdown dependency — small escaped HTML subset is enough for LLM answers
- Suggested follow-up chips submit immediately (same conversation) for faster live demos
- Insufficient-context path still shows the API answer text verbatim inside the distinct banner
- In-flight ask results are gated with `requestWorkspaceId` + `activeWorkspaceIdRef` so a workspace switch mid-request does not apply stale `conversation_id` / turns / errors (closure alone is insufficient after `await`)

## Known Limitations

- Non-streaming only (submit locked for the full round-trip)
- No persisted conversation picker across reloads / devices
- Markdown subset does not cover tables, fenced code blocks, or links
- No browser E2E covering indexed Northstar docs → cited answer
- Workspace switch mid-flight still shows the global submitting spinner until the orphaned request settles (`setSubmitting(false)` in `finally`)
