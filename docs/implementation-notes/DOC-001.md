# DOC-001 Implementation Note

## Summary

Implemented multipart document upload at `POST /workspaces/{workspace_id}/documents` with local filesystem storage, extension whitelist validation, configurable size limits, and `DOCUMENT_MUTATE` permission enforcement. Uploads persist a document row with status `uploaded` and store bytes under `{STORAGE_PATH}/{workspace_id}/{document_id}/{filename}`.

## Behavior Added

- `POST /workspaces/{workspace_id}/documents` accepts `multipart/form-data` with required `file` and optional `title`, `source_type`.
- Allowed extensions: `.md`, `.txt`, `.pdf`, `.json` (case-insensitive).
- Rejects files larger than `MAX_UPLOAD_BYTES` with `422 file_too_large`.
- Rejects unsupported extensions with `422 unsupported_file_type`.
- Owner, Admin, and Member roles may upload; Viewer receives `403 forbidden`.
- Successful upload returns `201` with document metadata and status `uploaded`.
- Default `title` is the uploaded filename; default `source_type` is `general`.
- File bytes written via local storage adapter; `storage_key` persisted on the document row.

## Decisions Made

- Returns `201` with flat `DocumentResponse` (not `202` with ingestion job wrapper) because ING-001 ingestion enqueue is deferred per Gate 1.
- Document UUID generated in service before storage write so storage keys are stable and path-safe.
- S3 adapter deferred; factory raises `NotImplementedError` for non-local backends.
- No upload audit event (AUDIT-001 deferred).
- No magic-byte or empty-file validation (DOC-002 deferred).

## Known Limitations

- Ingestion job is not created after upload (ING-001 deferred).
- No `document_upload` audit event (AUDIT-001 deferred).
- S3 storage backend not implemented.
- API response omits `ingestion_job` block from full API design until ING-001 lands.
