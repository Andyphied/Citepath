# WS-007 Implementation Note

## Summary

Added `WorkspaceScopedRepository` as the infrastructure base for tenant-owned queries and introduced minimal workspace-scoped repositories for documents, ingestion chunks, RAG conversations, and agent runs. A Docker-backed security test suite verifies cross-workspace reads and vector search cannot leak data between workspaces.

## Files Changed

| File | Change |
|------|--------|
| `app/infrastructure/db/scoped_repository.py` | New `WorkspaceScopedRepository` base with `_scoped_filter` and `get_by_id` |
| `app/modules/documents/repository.py` | New `DocumentRepository` — create, get_by_id, list_for_workspace |
| `app/modules/ingestion/repository.py` | New `IngestionRepository` — chunk CRUD + workspace-filtered `search_similar` |
| `app/modules/rag/repository.py` | New `RAGRepository` — create/get conversation, get message by id |
| `app/modules/agents/repository.py` | New `AgentRepository` — create/get agent run |
| `app/infrastructure/db/enums.py` | Added `values_callable` so SQLAlchemy persists enum values (required for repository writes) |
| `tests/security/test_workspace_isolation.py` | Cross-workspace isolation tests |
| `stories/ws-007-workspace-scoped-data-access-layer.md` | Status set to `in_progress` |

## Behavior Added

- All tenant-owned repository methods require an explicit `workspace_id` keyword argument.
- `_scoped_filter` applies `WHERE workspace_id = :workspace_id` to SQLAlchemy select statements.
- `IngestionRepository.search_similar` orders by pgvector cosine distance and always scopes by workspace.
- `WorkspaceRepository` intentionally does **not** extend `WorkspaceScopedRepository` (workspaces are not tenant-owned child entities).

## Tests Added

- `tests/security/test_workspace_isolation.py` — document/chunk/conversation/agent run cross-workspace `get_by_id` returns `None`; chunk list and vector search exclude other workspaces; listing chunks for a foreign document id under the wrong workspace returns empty.

## Decisions Made

- Repository `create` methods commit immediately, matching existing `AuthRepository` / `WorkspaceRepository` conventions.
- Vector search uses `DocumentChunk.embedding.cosine_distance()` per ADR-002; workspace filter is applied after building the similarity query.
- SQLAlchemy 2.0 persists enum `.name` by default; added `values_callable` to all PostgreSQL enums so lowercase DB values (`owner`, `indexed`, etc.) are written correctly.
- Isolation tests use `monkeypatch.chdir(REPO_ROOT)` so Alembic resolves `app/migrations` when conftest switches cwd to a temp directory.
- API-level 404/403 acceptance criterion for direct chunk access is deferred until DOC-004 document detail routes exist; repository layer returns `None` for cross-workspace lookups (services map to 404 per ADR-005).

## Known Limitations

- No row-level security policies (optional hardening per story notes).
- `get_message_by_id` is implemented but not covered by dedicated isolation tests (conversation coverage validates the same pattern).
- Usage and audit repositories remain unscoped in this story (future stories as needed).
- No API routes wired to these repositories yet.

## Follow-up Items

- **DOC-004+:** Wire document routes to `DocumentRepository`; map `None` lookups to 404.
- **RET/RAG stories:** Use `IngestionRepository.search_similar` from retrieval service.
- **Optional:** PostgreSQL RLS as defense-in-depth per ADR-005 alternatives.
