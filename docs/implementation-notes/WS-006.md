# WS-006 Implementation Note

## Summary

Introduced FastAPI workspace context dependencies so all `/{workspace_id}` routes verify membership before handlers run. Non-member and unknown-workspace access returns 403 with `failed_authorization` audit events including client IP. Member-management routes use `RequireManageMembersDep`, moving matrix enforcement out of `WorkspaceService` while preserving domain rules (last-owner, admin→owner escalation).

## Step 4 Fixes (Gate 3 Security Review)

- **Route-specific audit action on non-member denial:** `get_workspace_context_factory(denial_action)` parameterizes the audited action — read routes use `VIEW_DOCUMENTS`; `RequireManageMembersDep` uses `MANAGE_MEMBERS` (restores WS-005 audit semantics on member-management routes).

## Behavior Added

- `get_workspace_context` loads membership, validates workspace exists, builds `WorkspaceContext`, and records `failed_authorization` with `reason: non_member` and `ip_address` on denial.
- `require_permission(action)` factory enforces matrix checks with IP propagation via `PermissionService.require`.
- `GET /workspaces/{workspace_id}` uses `WorkspaceContextDep`; member routes use `RequireManageMembersDep`.
- `POST /workspaces` and `GET /workspaces` unchanged (no workspace_id in path).
- Service layer receives pre-validated context; domain rules remain for admin→owner and last-owner constraints.

## Tests Added

- `tests/api/test_workspace_context.py` — non-member 403, unknown workspace 403, member succeeds, audit includes IP on denial.
- Updated `tests/unit/test_workspace_service.py` for context-based service signatures.

## Decisions Made

- Non-member denial uses `PermissionAction.VIEW_DOCUMENTS` as the audit action for generic workspace access (consistent with prior `get_workspace` behavior).
- TestClient reports IP as `"testclient"`; production uses `request.client.host`.
- Matrix permission checks live exclusively in FastAPI deps for member-management routes; service no longer duplicates `MANAGE_MEMBERS` enforcement.

## Known Limitations

- RAG retrieval isolation AC ("Given I belong to Workspace A, retrieval only searches Workspace A documents") deferred — no RAG routes exist yet; dependency chain is structurally ready for future `require_permission(QUERY_RAG)` wiring.
- Document, RAG, agent, and admin routes not yet wired to workspace context (future stories).
- Repository base class workspace scoping deferred to WS-007.
- `X-Forwarded-For` is not parsed; only `request.client.host` is recorded.
