# UI-001 Implementation Note

## Summary

Added a Next.js (App Router) + TypeScript + Tailwind app under `web/` with a shared Citepath app shell (sidebar + header), typed API client with JWT bearer injection, workspace switcher wired to `GET /workspaces`, auth redirects to `/login`, and a Compose `web` service on port 3000. Minimal CORS support on the API enables browser calls from the UI origin.

## Behavior Added

- App shell branded **Citepath** with nav stubs: Documents, Ask, Agent, Admin
- Admin nav disabled unless active workspace role is `owner` or `admin`
- `NEXT_PUBLIC_API_URL` configures API base (default `http://localhost:8000`)
- `apiFetch` injects `Authorization: Bearer <token>` from `citepath_token` cookie
- Workspace switcher loads memberships, persists active id in `localStorage`, exposes `workspacePath()` for `/workspaces/{id}/...` calls
- Unauthenticated visits to protected routes redirect to `/login?next=...`
- Login page is a stub (UI-002) with temporary JWT paste helper for local demos
- Loading / error states on workspace fetch failures
- Compose builds and serves `web` alongside API/worker

## Tests Added

## Decisions Made

- **npm** (not pnpm) — pnpm not available in the environment; lockfile is `package-lock.json`
- Cookie-based token (`citepath_token`) so Next.js middleware can redirect before render; UI-002 may move to httpOnly session handling
- Path-based workspace context (not a custom header) matching existing FastAPI `/{workspace_id}` routes
- CORS defaults in `ENVIRONMENT=development` only; production must set `CORS_ORIGINS` explicitly
- JWT paste on `/login` is a scaffold convenience until UI-002 email/password forms exist

## Known Limitations

- No real login/register UI (UI-002)
- Feature pages are stubs (UI-003–UI-006)
- Admin route URL is still reachable for non-admins; only the nav item is role-gated
- `NEXT_PUBLIC_API_URL` is compile-time for production Docker builds (build arg)
- No end-to-end browser tests in CI yet

## Fix cycle (Gate 3 → Gate 4)

**Finding:** Login stub treated any `next` starting with `/` as safe, allowing open redirects via protocol-relative values (`//evil.example`).

**Change:**
- Added shared `sanitizeNextPath` in `web/src/lib/auth/safe-next.ts`
- Login stub redirects only through the sanitized path (defaults to `/`)
- Middleware writes `next` via the same helper for defense in depth
- Unit tests cover `//evil.example`, `https://evil.example`, `/documents`, backslash/scheme tricks, and empty/null defaults
