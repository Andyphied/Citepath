# WS-005 Implementation Note

## Summary

Centralized workspace RBAC in `PermissionService` with a static role-to-action matrix aligned to `docs/09-security-and-rbac.md`. Introduced `WorkspaceContext` and `PermissionAction` types. Refactored `WorkspaceService` member-management methods to use `PermissionService.require(..., MANAGE_MEMBERS)` instead of inline `_INVITE_ROLES`. Permission denials write a minimal `failed_authorization` audit event when an `AuditRepository` is configured.

## Step 4 Fixes (Gate 3 Security Review)

Addressed security review REQUEST CHANGES:

- **Non-member audit:** `_require_manage_members` and `get_workspace` call `PermissionService.record_authorization_failure` with `reason: non_member` before raising 403.
- **Admin→Owner escalation audit:** `_raise_admin_owner_forbidden` records `failed_authorization` with `reason: admin_owner_escalation_blocked`.
- **API audit persistence tests:** Added `test_invite_member_viewer_records_failed_authorization_audit` and `test_invite_member_non_member_records_failed_authorization_audit` asserting real `audit_logs` rows after 403.
- **Unit test:** `test_record_authorization_failure_supports_non_member_reason`.

## Behavior Added

- `PermissionService.is_allowed(context, action)` evaluates the static matrix.
- `PermissionService.require(context, action)` raises `WorkspaceForbiddenError` on denial and appends `failed_authorization` audit metadata (`action`, `role`) when an audit repository is present.
- `PermissionService.record_authorization_failure(...)` supports explicit denial recording for non-member and escalation paths.
- `WorkspaceService.invite_member`, `update_member_role`, and `remove_member` enforce `MANAGE_MEMBERS` via the permission service; Admin-cannot-assign/modify-Owner and last-owner rules remain as domain constraints after the matrix check.
- Non-member workspace access and insufficient-role denials both persist `failed_authorization` audit events when wired via `deps.py`.

## Tests Added

- `tests/unit/test_permission_service.py` — parameterized permitted/denied pairs for all roles and actions; explicit acceptance cases (Viewer + `DOCUMENT_MUTATE` denied; Member + `QUERY_RAG` / `RUN_AGENT` allowed); audit-on-deny behavior; non-member reason recording.
- `tests/api/test_workspaces_invite_member.py` — API tests asserting `audit_logs` persistence on Viewer and non-member 403 paths.

## Decisions Made

- Used event type `failed_authorization` per security doc (not `authz.denied`).
- `PermissionService` accepts optional `AuditRepository`; unit tests and legacy workspace service construction use a no-audit default instance.
- `QUERY_RAG` and `RUN_AGENT` are separate enum values with identical matrix rows for future route-level granularity.
- Non-member denials use `record_authorization_failure` with `reason: non_member`; full FastAPI dependency chain deferred to WS-006.

## Known Limitations

- No FastAPI `get_workspace_context` / `require_permission` dependencies (WS-006).
- Document, RAG, agent, and admin routes do not yet call `PermissionService` (future stories).
- `DELETE_WORKSPACE` is matrix-only; no delete endpoint yet.
- Full AUDIT-005 rate limiting and IP propagation from HTTP layer not implemented.
