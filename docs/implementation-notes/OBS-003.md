# OBS-003 Implementation Note

## Summary

Added `RequestIdMiddleware` as the first middleware in the FastAPI chain. Each HTTP request receives a UUID4 request ID (or accepts a client-provided `X-Request-ID`), stores it on `request.state.request_id` and in an async context variable, and returns the ID in the `X-Request-ID` response header.

## Behavior Added

- Reads optional `X-Request-ID` request header; uses trimmed value when non-empty and ≤128 chars.
- Generates UUID4 when header is absent, blank, or over length limit.
- Sets `request.state.request_id` for handlers and exception handlers.
- Sets async context via `set_request_id()` / `get_request_id()` for code paths without direct `Request` access (OBS-002 logging).
- Exposes `get_request_id_from_request(request)` for OBS-004 error envelope integration.
- Returns `X-Request-ID` on all HTTP responses, including error responses (401 tested).

## Decisions Made

- **Module location** — Placed under `app/modules/observability/` per `docs/04-module-boundaries.md` (not a top-level `middleware/` folder).
- **Middleware order** — Registered with `add_middleware` after app creation; last added runs first on ingress. Future middleware (e.g. OBS-002 request logging) must be registered *before* `RequestIdMiddleware` to preserve request ID as first in chain.
- **Client ID validation** — Accept any non-empty trimmed string ≤128 chars (not strictly UUID) so upstream tracing systems can pass opaque IDs.
- **Error body `request_id` deferred** — OBS-004 will add `request_id` to JSON error payloads; this story only provides storage/context helpers.
- **Structured logging deferred** — OBS-002 will consume `get_request_id()` / `request.state.request_id`; no log lines added here.
- **Celery propagation deferred** — Task header propagation documented in `docs/11-observability.md` but out of MVP story scope.

## Known Limitations

- No Celery task header propagation yet.
- No structured request-completion log line (OBS-002).
- Error JSON bodies do not yet include `request_id` (OBS-004).
- Overlong client IDs are replaced with a new UUID rather than truncated.

## Follow-up Items

- **OBS-002:** Structured logging using `get_request_id()` and `request.state.request_id`.
- **OBS-004:** Include `request_id` in standard error envelope via `get_request_id_from_request()`.
- **Optional:** Propagate request ID to Celery tasks via task headers when background jobs are tied to API requests.
