# ING-002 Implementation Note

## Summary

Implemented workspace-scoped text extraction for uploaded documents (MD, TXT, JSON, PDF). The ingestion worker reads stored files via `StorageBackend.get`, extracts structured text segments (with per-page metadata for PDFs), fails jobs on corrupt or empty extraction, and leaves successful jobs in `processing` for ING-003 chunking.

## Behavior Added

- `StorageBackend.get(storage_key)` reads persisted upload bytes from local storage.
- `extract_document_text(file_type, content)` returns `ExtractionResult` with `ExtractedSegment` list.
- PDF extraction uses `pypdf` per page; each segment includes `metadata.page_number` (1-based).
- JSON extraction collects nested string values; falls back to pretty-printed JSON when no strings exist.
- MD/TXT decode as UTF-8; empty or whitespace-only content raises `ExtractionError`.
- Worker calls extraction after transitioning job/document to `processing`.
- Extraction failure sets job `failed`, document `failed`, stores truncated `error_message`, logs `ingestion_extraction_failed`.
- Successful extraction logs `ingestion_extraction_completed`; job/document remain `processing`.

## Decisions Made

- Extraction result is segment-based (`ExtractedSegment` + metadata) so ING-003 can preserve PDF page numbers without re-parsing.
- Error messages truncated to 2048 characters per ingestion pipeline doc.
- Encrypted PDFs treated as permanent extraction failures.
- Worker uses `create_storage_backend(get_settings())` rather than importing route-layer dependencies.
- Successful extraction does not advance job to `completed`; ING-003+ owns downstream pipeline steps.

## Known Limitations

- No OCR for scanned/image PDFs.
- JSON numeric/boolean-only payloads stringify via `json.dumps` rather than failing.
- S3 storage backend still unimplemented; `get` only on local adapter.
- Extraction result is not persisted yet; held in-memory until ING-003 chunking is wired.

## Step 5b Platform Follow-up (2026-07-07)

Defense-in-depth storage hardening from security re-review:

- Added `app/infrastructure/storage/validation.py` with `reject_unsafe_storage_key()` — rejects empty keys, absolute paths, `.`, `..`, and empty path segments.
- `LocalStorageBackend.get()` validates keys before path resolution (in addition to `Path.is_relative_to()`).
- `process_ingestion_job` calls the same validator after prefix check and before storage read.
- Tests: `tests/unit/test_storage_validation.py`, embedded `..` segment tests in `test_local_storage.py` and `test_ingestion_tasks.py`.
